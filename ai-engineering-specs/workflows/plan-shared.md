# 实现 Plan 共用机制

本文件不是独立任务入口。当某个 workflow 声明进入实现 Plan、补 Plan，或引用本文件时，**必须先完整加载本文件**，再与该 workflow 中的分级条件、Plan 字段语义一并执行。

分级条件（何时必须 / 可跳过 Plan）与 Plan 正文字段的业务含义，由引用方 workflow 定义。本文件只约定载体、软提示、确认门禁与中途叫停。

## Plan 载体与落盘（S1）

- **默认载体是当前对话**：输出可审阅的 Plan 正文，等待用户确认即可。不强制切换任何 IDE 的 Plan Mode，不强制写入仓库或本地文件。
- **禁止擅自落盘**：未经用户明确要求，不得把 Plan 写成项目文件。
- **持久化由用户发起**：用户明确要求保存时才落盘；保存路径由用户指定，或由 Agent 给出可选项并标明推荐项后等用户选定。业务可用 `ai-engineering-overlay/` 加严落盘规则；本机制不规定唯一目录。
- **禁止**把业务实现 Plan 写入 `ai-engineering-specs/`（规范正文目录只放规范，不放过程产物）。

## 环境软提示（T1）

在引用方已判定「必须出 Plan」，且即将进入 / 正在进入 Plan 时，按当前对话环境**主动软提示一次**（提醒 + 可选捷径，不是门禁）：

- **Cursor**：提示可切换到 Plan Mode 审阅；并说明用户也可要求「就在当前对话出 Plan」。
- **其他对话框 / 工具**：提示在本对话审阅确认 Plan，或遵循该工具自有的方案审阅方式；同样允许用户要求直接在当前对话继续。

用户已明确「就在当前对话出 Plan」时，本轮不再反复提示切换。软提示不等于强制切换；未切换时仍须在当前对话输出完整 Plan 并等待确认。

## 软提示触发时机

- **引用方的前置阶段未完成时不得提示**（例如需求未决、行为基线或结构范围未确认）。
- **已判定可跳过 Plan 时不得提示**。
- **触发点**：前置阶段已完成，且引用方已判定必须出 Plan 之后、输出 Plan 之前或紧挨着输出 Plan 时，主动提示一次。
- **中途叫停补 Plan**：重新进入 Plan 时再提示一次（规则同上）。

## Plan 确认门禁

- 引用方已判定必须出 Plan 时：先按引用方规定的字段输出 Plan，等待用户确认；未确认前不得写实现代码。确认以用户明确回复为准，不依赖是否切换 Mode、是否落盘。
- 用户确认后，仅按确认版 Plan 进入引用方的编码 / 改码阶段。

## 中途叫停与补 Plan

用户在编码或改码过程中以任意明确语义要求暂停并先对齐实现方案时（例如「停，先补 Plan」「暂停开发，出实现方案」），执行本段，优先级高于继续改码。

1. **立即停止编码**，不再继续改文件。
2. **盘点现状**：已改/已创建的文件、当前进度、与目标的差距。
3. 按「环境软提示（T1）」与「软提示触发时机」提示一次，再**补一份短 Plan**。Plan 字段语义遵循引用方 workflow；载体与落盘遵循本节 S1。若已有改动，Plan 中必须另列「已改代码处理」三项可选项，并标明推荐项：
   - 保留继续
   - 回滚重做
   - 局部调整
4. **等待用户确认** Plan 及「已改代码处理」选项；未确认前不得继续写实现代码，也不得擅自回滚或继续改。
5. **确认后**按确认版 Plan 与所选处理方式继续；交付时注明「中途叫停补 Plan」及最终处理方式。

## 共用禁止动作

- 未经用户明确要求擅自将 Plan 落盘，或把业务 Plan 写入 `ai-engineering-specs/`。
- 将切换 Plan Mode 或落盘当作确认门禁（未切换、未落盘不得拒绝在对话中完成 Plan 确认）。
- 中途叫停后，在用户未确认前擅自回滚、继续改，或跳过补 Plan。
