# 新功能开发标准作业流程 (SOP)

## 进入条件

- 用户任务命中本流程的索引触发项。
- 任务类型已经明确是新增能力或新模块，而不是缺陷修复。

## 强制加载

进入实现 Plan、补 Plan、P-A / P-B 选择，或执行与 Plan 载体 / 软提示 / 叫停相关步骤前，必须完整加载 [`./plan-shared.md`](./plan-shared.md)。

## 阶段一：上下文与未决问题

1. 检查现有代码风格、状态管理与目录结构，列出受影响文件。
2. 列出会影响行为的未决问题。每一项给出可选项，并标明推荐项。
3. 未决问题清单非空时，停止在本阶段，等待用户确认。不得进入编码或实现 Plan。
4. 即使用户要求「直接实现」或「先出 Plan」，仍执行本阶段硬拦：继续列出未决可选项并标明推荐项；不得放行，不得提供「跳过未决」类选项（与总纲「需求澄清」一致）。

## 阶段二：实现 Plan（分级）

在未决问题清单为空之后，先判定是否需要实现 Plan：

1. **可自动跳过**：按下方跳过条件进入阶段三（不必问 P-A / P-B）。
2. **必须出 Plan**：先执行 `plan-shared.md` 的「阶段入口选择（G1）」——**仅**给出 P-A / P-B 并等待选定；**未选定前不得输出 Plan 正文、不得编码**。选 P-A 后再出 Plan 并等待确认；选 P-B 后进入阶段三。

载体、软提示、确认门禁与中途叫停见 `plan-shared.md`。

### 必须出 Plan 的条件（满足任一即必须）

- 预估触及 **3 个及以上** 源文件（不含纯生成的 lock / 产物）。
- 跨层改动：同时涉及下列两类及以上——API / 数据层、store / 状态、路由、页面或组件、构建或 CI 配置。
- 存在两种及以上合理实现路径，且会影响文件边界或对外接口。
- 需要分多步交付，或含数据迁移 / 改名扩散。

### 可自动跳过 Plan 的条件（须同时满足）

- 未决问题清单为空（或已全部确认）。
- 实现路径唯一，无架构或接口分叉。
- 受影响面小：**同一模块内，且预估触及源文件不超过 2 个**。
- 不满足上方任何一条「必须出 Plan」条件。

同时满足时：**自动跳过 Plan 与 P-A / P-B，直接进入阶段三**。交付说明中须注明「已按简单任务跳过实现 Plan」。边界不确定时按「必须出 Plan」处理，不得从宽跳过。

### Plan 内容（本流程字段语义）

必须包含：目标、受影响文件、步骤顺序、关键取舍、验收点。此即本流程唯一的实现 Plan 形态，精炼可执行，不得写成完整设计说明书，也不存在另一档「详细 Plan」。

- **目标**：本次要落地的能力或模块结果。
- **受影响文件**：实现将触及的文件与模块。
- **步骤顺序**：编码与接线顺序。
- **关键取舍**：实现路径分叉及推荐。
- **验收点**：如何确认能力已按约定工作。

## 阶段三：模块化编码

在「已确认 Plan」「已合法跳过 Plan」或「用户已选定 P-B」之后：

- 编写高内聚、低耦合的代码。
- 遵守 `rules/` 中已命中的技术底线。

## 阶段四：静态检查与交付

- 运行项目已有的类型检查、编译或测试命令。
- 向用户说明改了什么、如何验证、还有哪些限制。
- 若曾跳过 Plan、用户选定 P-B、中途补 Plan，或对已改代码做了保留/回滚/局部调整，须在交付说明中写明。

## 中途叫停

编码过程中用户要求先对齐方案时，执行 `plan-shared.md` 的「中途叫停与补 Plan」；补出的 Plan 字段语义遵循本流程「Plan 内容」。

## 禁止动作

- 主流程能走通就视为需求已确定。
- 在未决问题尚未确认时写实现代码或实现 Plan；或以用户要求直接实现 / 先出 Plan 为由放行。
- 在必须出 Plan 时，未完成阶段入口 P-A / P-B 选定就输出 Plan 正文或写实现代码。
- 在必须出 Plan 时，用户已选 P-A 但尚未确认 Plan，就写实现代码。
- 违反 `plan-shared.md` 中的共用禁止动作。

## 完成标准

- 未决问题均已确认，或清单为空。
- 必须出 Plan 时：已完成阶段入口 P-A / P-B；若选 P-A，Plan 已确认；若选 P-B，交付已注明跳过。或已按简单任务条件合法跳过 Plan。若曾中途叫停，补 Plan 与已改代码处理方式均已确认。
- 静态检查已执行，并在交付说明中写明结果。
