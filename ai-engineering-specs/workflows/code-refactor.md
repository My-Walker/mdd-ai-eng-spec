# 重构标准作业流程 (SOP)

## 进入条件

- 用户任务命中本流程的索引触发项。
- 任务是调整已有代码的结构，不是新增能力，也不是纠正缺陷。

## 强制加载

进入结构实施 Plan、补 Plan、P-A / P-B 选择，或执行与 Plan 载体 / 软提示 / 叫停相关步骤前，必须完整加载 [`./plan-shared.md`](./plan-shared.md)。

## 阶段一：行为基线与结构范围

1. 列出受影响文件，以及这次要做的结构调整，例如拆分、合并、改名或抽离。
2. 写下必须保持不变的可观察行为。已有测试、入口或最小脚本能核对的，先记下核对方式。
3. 结构方案不止一种，且会改变文件边界或对外接口时，列出可选项并标明推荐项。
4. 行为基线或结构范围仍未确定时，停止在本阶段，等待用户确认。不得进入改码或结构实施 Plan。
5. 即使用户要求「直接改」或「先出 Plan」，仍执行本阶段硬拦：继续确认基线与范围（含结构方案选项）；不得放行，不得提供「跳过未决」类选项（与总纲「需求澄清」一致）。

## 阶段二：结构实施 Plan（分级）

在行为基线和结构范围都已确认之后，先判定是否需要结构实施 Plan：

1. **可自动跳过**：按下方跳过条件进入阶段三（不必问 P-A / P-B）。
2. **必须出 Plan**：先执行 `plan-shared.md` 的「阶段入口选择（G1）」——**仅**给出 P-A / P-B 并等待选定；**未选定前不得输出 Plan 正文、不得改码**。选 P-A 后再出 Plan 并等待确认；选 P-B 后进入阶段三。

载体、软提示、确认门禁与中途叫停见 `plan-shared.md`。

阶段一已选定的结构方案不得在 Plan 中再问一遍；Plan 只覆盖如何安全走完已确认范围。

### 必须出 Plan 的条件（满足任一即必须）

- 预估触及 **3 个及以上** 源文件，或会改变文件边界、对外接口。
- 迁移 / 改名 / 抽离步骤存在先后依赖，或需要分多步交付。
- 存在尚未确认的实施分叉（在已选结构方案之内），且会影响改码顺序或风险面。

### 可自动跳过 Plan 的条件（须同时满足）

- 行为基线与结构范围均已确认。
- 实施路径唯一，无待确认的实施分叉。
- 受影响面小：**同一模块内，预估触及源文件不超过 2 个**（例如单文件改名或单文件内小范围抽离）。
- 不满足上方任何一条「必须出 Plan」条件。

同时满足时：**自动跳过 Plan 与 P-A / P-B，直接进入阶段三**。交付说明中须注明「已按简单重构跳过结构实施 Plan」。边界不确定时按「必须出 Plan」处理，不得从宽跳过。

### Plan 内容（本流程字段语义）

必须包含：目标、受影响文件、步骤顺序、关键取舍、验收点。此即本流程唯一的结构实施 Plan 形态，精炼可执行，不得写成完整设计说明书，也不存在另一档「详细 Plan」。

- **目标**：要完成的结构调整，并写明不改变阶段一列出的可观察行为。
- **受影响文件**：拆分、合并、改名或抽离涉及的文件。
- **步骤顺序**：迁移、改名、抽离的先后顺序。
- **关键取舍**：仅补充已选结构方案之内、尚未确认的实施分叉及推荐；勿重复阶段一的结构路线选择题。
- **验收点**：阶段一记下的行为基线核对方式。

## 阶段三：只调整结构

在「已确认结构实施 Plan」「已合法跳过 Plan」或「用户已选定 P-B」之后：

- 只改已确认范围内的结构。
- 不新增能力，也不改掉缺陷的对外结果。
- 遵守 `rules/` 中已命中的技术底线。

## 阶段四：对照基线与交付

- 用阶段一记下的方式再核对一遍必须保持的行为。
- 运行项目已有的类型检查、编译或测试命令。
- 向用户说明结构改了什么、哪些行为保持不变、用什么核对，以及哪些项没核对到。
- 若曾跳过 Plan、用户选定 P-B、中途补 Plan，或对已改代码做了保留/回滚/局部调整，须在交付说明中写明。

## 中途叫停

改码过程中用户要求先对齐方案时，执行 `plan-shared.md` 的「中途叫停与补 Plan」；补出的 Plan 字段语义遵循本流程「Plan 内容」。

## 禁止动作

- 把重构当成补需求或修缺陷。
- 行为基线或结构范围尚未确认时改代码或出结构实施 Plan；或以用户要求直接改 / 先出 Plan 为由放行。
- 在必须出 Plan 时，未完成阶段入口 P-A / P-B 选定就输出 Plan 正文或改代码。
- 在必须出 Plan 时，用户已选 P-A 但尚未确认 Plan，就改代码。
- 没有基线核对结果时声称行为不变。
- 违反 `plan-shared.md` 中的共用禁止动作。

## 完成标准

- 行为基线和结构范围均已确认。
- 必须出 Plan 时：已完成阶段入口 P-A / P-B；若选 P-A，Plan 已确认；若选 P-B，交付已注明跳过。或已按简单重构条件合法跳过 Plan。若曾中途叫停，补 Plan 与已改代码处理方式均已确认。
- 交付说明写明结构变化、行为核对结果；无法核对的项写明原因。
- 静态检查已执行，并在交付说明中写明结果。
