# Git 提交规范

1. **提交时机**：只有用户明确要求提交时才创建 commit。完成功能或修复缺陷后不得自行提交。
2. **说明语言**：commit message 使用简体中文，简洁说明这次修改的内容。
3. **说明格式**：`<类型>: <简短中文描述>`。示例：`feat: 添加用户注册功能`。
4. **类型选取**：沿用当前仓库近期提交已经使用的类型。没有先例时，在 `feat`、`fix`、`docs`、`chore` 中选最贴切的一个。
5. **提交范围**：工作区里如果同时有多组改动或未跟踪文件，不得自行决定只提交其中一部分。先列出可选项并标明推荐项，等用户选择后再执行 `git add` 和 `git commit`。可选项至少包括「全部纳入」，以及按路径分开的每一组；用户也可以自己指定范围。只有工作区里的全部改动都属于同一次提交时，才可以不询问直接提交。
